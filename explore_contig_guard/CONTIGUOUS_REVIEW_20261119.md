## 一、基线 4902ae4a 的连续访存路线

基线的连续访存计价有 **3 条路线**（不含 strided/indirect 等非连续域）：

| # | 路线 | 给谁 | 定价方式 | 多 load 并行 | for 处理 |
|---|---|---|---|---|---|
| 1 | 逐访问解析式（+ simt 按 W 分档吞吐表） | simd 与 simt 各一套；**每条 load/store 独立计价** | simd：`启动 + 字节/带宽`，load 105.31 cycle + 167.56 B/cycle、store 90.95 + 213.13（联合拟合常数，全部形状共用）；simt：`warp 指令数 / 吞吐`，吞吐按启动 warp 数 W∈{1..32} 逐档实测 | **无**——各条访问独立计价后相加，条与条之间的并发/排队不建模 | **无 for 概念**——循环体也按同样的逐访问式计价 |
| 2 | 独立 load 组聚合包络（independent_loop_load_group） | simd | **流水段开头 1–4 条连续 FP32 load** 攒成一组：内核启动 546.1 + 迭代启动 12.8 + 字节/83.26 B/cycle | **有**——但仅此一个特例（形状限定 FP32、必须前缀、单一聚合带宽） | 不区分 |
| 3 | 循环体：无独立模型 | 所有带 for 的循环体 | 沿用路线 1 的逐访问公式按 K **线性外推**（每 op 启动 + 字节/带宽）×K | 同路线 1（无） | 有 K，但只是乘法 |

**不足（引出全面重标定）**：

1. **单访问口径、无组结构**：同形状多条访问在 MTE 队列里的并发摊薄
   （第 1 条全价、后面打折）没有参数，多波聚合带宽摊薄也没有——
   vector_add（每程序 2 load + 1 store、97 程序 2 波）被高估
   **+29.86%**。
2. **循环体缺位**：路线 3 不是模型——直线逐 op 公式按 K 线性外推。
   循环体的真实行为是"固定启动头 + 每轮稳态斜率"（G3：T(4)=4211ns
   ≈ T(16)=3881ns，几乎不变，K=64 才线性涨到 8905ns），线性外推在
   K=4 处差 **4 倍**。
3. **组效应特例**：路线 2 只覆盖"前缀 1–4 条 FP32 load"一个形状，
   是补丁不是机制。

这三条不足指向同一个结论：需要**按循环体/直线体分域、各自建立
带物理结构的标定公式**。下面先定义两个域，再分别展开公式。

## 二、直线域与循环域：定义、样例与分域依据

### 2.1 定义与代码样例

costmodel 把 kernel 拆成 stage；一个访存 stage 的访问有没有被
**运行期循环**包住，决定它属于哪个域：

```python
# 直线域：没有 scf.for 包住，每条访问每个 program 只执行一次
@triton.jit
def add_kernel(x_ptr, y_ptr, out_ptr, n, BLOCK: tl.constexpr):
    pid  = tl.program_id(0)
    offs = pid * BLOCK + tl.arange(0, BLOCK)
    mask = offs < n
    x = tl.load(x_ptr + offs, mask=mask)       # 访问 1（与 2 独立）
    y = tl.load(y_ptr + offs, mask=mask)       # 访问 2
    tl.store(out_ptr + offs, x + y, mask=mask)

# 循环域：真 scf.for 包住，每条访问执行 K 次
for sub in range(0, XBLOCK, XBLOCK_SUB):       # 运行期循环，K = XBLOCK//XBLOCK_SUB
    idx = base + sub + tl.arange(0, XBLOCK_SUB)
    v = tl.load(inp + idx)
    tl.store(out + idx, v * a + b)
```

判定标准是 IR 里是否还是真 `scf.for`：`tl.static_range`/constexpr
在编译期展开后与直线代码完全同价（E7 实证：static_range 展开 ≡
直线型，三组引擎全一致 <5%），所以展开的循环归直线域。

### 2.2 为什么分两个域建模——不只是"参数不同"，是公式形状不同

评审的自然质疑："整核时间差不多，边际也差得不多，参数调一调共用
一套公式不行吗？"——不行，三个实测依据：

**① 两条曲线的自变量和形状都不同（同工作量对照）。** 固定总搬运量
16KB，只变条数/写法（fp32，simd）：

| 写法 | 实测 ns/迭代 |
|---|---:|
| 循环，1×16KB | 200.7 |
| 循环，2×8KB | 197.5 |
| 循环，4×4KB | 196.8 |
| 直线组价公式（同总量）：n=1 / n=2 / n=4 | 264.1 / 196.7 / **269.9** |

循环域对条数**单调且 ±2% 平**（每轮发射节流，稳态斜率是上下文
常数）；直线域**非单调**——队列深 16 造成"前 Q 条摊薄、超 Q 换档"
的拐点结构（组价表的 first/marginal/cTransfer 三段式）。**一个
单调、一个有拐点**——这不是参数差异，是函数形状差异。

**② 时间-工作量曲线形状不同。** 循环体整核 = 固定启动头 A(P) +
K×稳态斜率（G3：T(4)=4211 ≈ T(16)=3881，几乎不变的头部 + 线性
区）；直线体没有 K，其价格随条数在队列深度处出现拐点后进入传输
受限线性区。两种曲线无法用一个公式族同时表达。

**③ 跨域复用的实测代价。** 把直线组价公式逐条套到循环体上：E26
15 点矩阵**系统性高估 +40~90%（MAPE≈65%）**——直线排队上下文的
边际在循环发射节流上下文不成立。反过来，基线路线 3（循环体用
直线逐 op×K）正是 G3 四倍差的来源。

**④ simt 佐证。** simt 循环混合体**超可加**：混合 ≈ 1.7-2.0×
（L+S）（E28b，clock64+排空修正）；simt 直线体无此现象记录。
两域的行为差异在 simt 上更显著。

（可进一步加强的实验：simt 直线混合体在同工作量下的对照测量、
锁态协议消除双峰干扰——列为标定战役事项。）

### 2.3 两个域各自的公式（概览）

- **直线域**（§三）：单发解析式 + 同形分组价（n≤Q / n>Q 两段）。
- **循环域**（§四）：simd = E27e 拟合模型（逐-nL/nS 传输曲线 +
  联合发射地板 + 逐 128B 行混合税 + tiny delta 表）；simt =
  load 曲线 + E17i 排空曲线，可加组合。
- 共享：候选层 A(P)、estimator 组合层、Tier 3 逐 op 兜底。

## 三、直线域公式

直线域先按**同形状**归组（组键 = 方向 × 元素个数 × 元素宽度 ×
掩码；n = 组内条数，不是 load+store 对数——1 条 4KB load + 1 条
4KB store 是两组、各自 n=1），每组算查表键
`方向/dtype/字节档/warm或cold`（字节档 = 字节按 log2 最近邻落入
32..16384 八档；warm/cold = 整 stage 足迹 ≤/> 128MB L2）。

### 3.1 为什么要分"单发"和"多访问组"

- **多访问组**（n≥2 且键命中）：同形状的多条访问在 MTE 队列里
  背靠背排队，第 1 条付全价（含 DRAM 延迟），第 2..Q 条只付边际
  价（队列深度把延迟摊薄）——这是**排队摊销**结构；
- **单发**（n=1）：没有"后面的访问排队摊薄"这回事，而且组价的
  first 是在"组内有兄弟访问"的上下文里标定的，孤发一条用它会
  双算发射开销——所以走**解析式**（与基线同源，route 报告逐位
  验证：4KB load = 129.75ns）。
- **未命中格 / 掩码组**也走解析式：表只标了有探针数据的 110 格；
  掩码组按活跃字节选档会与按满字节标定的表错配，故意不查。

### 3.2 公式

**单发 / 未命中 / 掩码（解析式，ns）**：

```
simd load：  T = 105.31 + 字节/167.56    （×波衰减 waves^−0.32，P>56 段）
simd store： T = 90.95 + 字节/213.13
simt：       T = warp 指令数 / 吞吐速率（GM/UB 按 W∈{1..32} 分档）
```

**多访问组（键命中，n≥2）**：

```
n ≤ Q：  T_group = first + (n−1) × marginal
n > Q：  T_group = first + (Q−1) × marginal + (n−Q) × kc × marginal
整组 × pAxisFactor(P)      （P≤56 恒 1.0；P>56 查多波摊薄曲线）
```

每一项的物理含义与实例（fp32/warm load，4KB 档）：

| 项 | 值 | 含义 |
|---|---:|---|
| first | 160.1 ns | 第 1 条付全价（含 DRAM 延迟与发射） |
| marginal | 36.6 ns | 第 2..Q 条的摊薄价（队列深 16 内多笔在飞） |
| Q | 16 | 队列深度：store 恒 8；load warm clamp(64KB/字节,4,32)、cold clamp(32KB/字节,4,8) |
| kc×marginal | 45.0 ns | 超过 Q 条后进入传输受限区的换档价 |
| pAxisFactor | P≤56=1.0 | 多波（P>56）聚合带宽摊薄曲线（E13） |

vector_add（每程序 2×4KB load + 4KB store）：load 组 n=2 →
160.1+36.6=196.7ns；store n=1 → 解析式 110.17ns；整核对账
2140.3 vs 实测 2141.0（−0.03%）。

### 3.3 参数针对哪些配置、各自几套

- 组价表按 **引擎 × 方向 × dtype × 字节档 × 驻留** 分格，每格
  `{first, marginal}` 2 个数：理论上限 128 格/引擎，实际标定
  **simd 48 格、simt 62 格**（simt 另有按激活 warp 数的 `/w<W>`
  变体格）；换档比 kc 每引擎 4 个标量；pAxis 每引擎 4 条曲线。
- 解析式：simd 每方向 2 个常数（启动 + 带宽）；simt 按 W 分档
  吞吐表（基线继承）。
- 覆盖（simd 载入侧逐键清点）：load/warm = fp16+fp32 全 8 档；
  load/cold = 4 dtype × {1024,4096,16384}；store = 4 dtype ×
  {1024,4096,16384}。落档是硬分箱（log2 最近邻 + 端点钳制），
  不做档间插值；落到的档没标定即"未命中"→ 解析式。

## 四、循环域公式

### 4.1 simd：E27e 拟合模型

**(a) 结构**：

```
L = 曲线_nL(lB)     每-nL 实测传输曲线：只含 load 的循环体在该条数
                    下逐字节实测点连成的分段线性折线；nL 介于两档
                    之间按 log2 插值，域外沿尾斜率延伸
S = 曲线_nS(sB)     每-nS store 曲线（同构）
floor = max(stepL[nL], stepS[nS], stepT[nL+nS])   发射节流地板
混合体（load、store 都有，store 非 tiny）：
    perIter = max(floor, L, S) + cL×(lB/128) + cS×(sB/128)
单方向：perIter = max(floor, 曲线)
tiny store（全 store ≤128B）：
    非归约 fed：perIter = max(stepT[nL], L) + excess表[dom](nS)
    归约 fed：  perIter = max(stepT[nL], L) + chain表[dom](nS)
整核 T = A(P) + K × perIter × 波衰减(waves^−0.05)
```

**(b) 每个成分是什么**：

- **L = 曲线_nL(lB)**：对每个 load 流数 nL∈{1,2,4,8}，单独测一族
  "只含 load 的循环体"，逐字节实测点连成分段线性折线。fp32 实例
  （nL=1）：32B→54.4、256B→55.0、1KB→65.7、4KB→78.7、8KB→92.4、
  16KB→140.0 ns/迭代。回答："每迭代用 nL 条 load 搬 lB 字节，
  load 侧稳态要多久"。覆盖：grid=1、热 L2、每方向 ≤32KB、
  域外延伸（fp32 已补 64KB 实测锚点 512.2ns）。
- **S = 曲线_nS(sB)**：同构，store 族 nS∈{1,2,4}。
- **floor**：发射节流地板。stepL[nL] = nL 条 load 的小字节体实测
  地板（fp32 {1:55, 2:59, 4:93, 8:191}——nL=8 时 191ns 就是 8 条
  指令的纯发射墙）；stepS 同理；**stepT[nL+nS] 是混合体联合发射
  墙**——nL+nS 条描述符共享同一个标量发射前端，一起发射比单
  方向更贵（小字节混合点直读 {3:97, 4:97, 5:102, 6:120, 8:146}）。
  取 max 防止曲线在小字节端插值出低于发射墙的价。
- **cL/cS 混合行税**：混合 adder 与两方向总字节成正比——
  MTE2/MTE3 双队列并行时共享下游（L2 端口/GM 控制器）的逐字节
  竞争串行化，store 方向不可隐藏比例（0.37ns/128B）是 load 方向
  （0.11）的 3.4 倍（E28：MD≡MI，依赖链否定）。
- **tiny excess/chain 表**：全 store ≤128B 的混合体，小 store 的
  完成往返超出流水隐藏容量的部分——按主导 load 字节分键的
  nS delta 表（E18b/E19 现象保留、97ns 常数改为几何敏感表）。

**(c) 拟合质量与限制**：

- 样内 MAPE（E27b/E27c 扫描，fp32）：全域 **6.9%**、loads 6.6%、
  mix 5.3%、tiny 12.5%；四 dtype 全域 6.9-12.4%。
- 已知限制：① 拟合条件 grid=1 热 L2；真实 kernel 是 grid=56 +
  DRAM 流式——同体实测 188 vs **597** ns/迭代（3.2×），
  memory_stream_l4 因此 −22.4%（唯一 flip，§3.1 的对照基线）；
  ② 混合 adder 的 (sB, nS, P) 曲面只标了 P=1 切片。

### 4.2 simt：load 曲线 + E17i 排空曲线（可加组合；组合律待定）

**(a) 结构**：

```
L = 曲线_nL(lB)      simt load 传输曲线：每 nL∈{1,2,4} 一条分段
                     线性实测折线（drain-forced 探针：窗口内放
                     dependent sink + barrier 强制 load 完成）
S = E17i排空曲线(sB) = (sB/128) × line_ns(sB)
                     simt store 走 GM → SIMT DCache(128B 行) →
                     线程寄存器，每行回填按 E17i 实测排空率计
                     （L2 档：4KB 6.22 / 8KB 6.46 / 16KB 6.08 /
                      32KB 6.08 ns/行）
perIter = L + S      可加组合（E17g：simt 的 load/store 流无重叠）

tiny store（全 store ≤128B）：
    perIter = max(stepL[nL], stepT[nL], L) + excess/chain表[dom](nS)
```

**(b) 数据通路对照（为什么 simt 与 simd 组合不同）**：simd 是
GM → UB（MTE2/MTE3 直传，两通道可并行 → 取瓶颈 max）；simt 是
GM → SIMT DCache（128B 行回填）→ 线程寄存器，**load 与 store
串行** → 可加。

**(c) 拟合质量**：load 曲线四 dtype MAPE 1.0-16.5%（逐 nL 实测
节点直读）；store 侧 = E17i 数据本身（已被 E28b 单点验证：4KB
store 203.9 ≈ E17i 199.1）。

**(d) 已知限制（组合律待定，如实记录）**：

1. **simt 混合组合律未定式**。E28b（grid=1，clock64，drain 修正，
   3 遍 ±0.1ns）实测：混合体对总字节线性（8KB→1268.4、32KB→
   5165.2，~6.3 B/ns），**流数完全不影响**（(1L,1S)/(2L,1S)/
   (2L,2S)/(1L,2S) 差 <0.2%），且混合 ≈ 1.7-2.0× 可加（超可加，
   E6/E1 的 store 干扰记录一致）——可加组合在混合体上偏乐观。
2. **SYS_CNT 窗口在 simt 混合体上饱和（计数器伪影，E28c profiler
   交叉验证）**：8/12/12/16KB 四种混合体的 clock64 读数完全相同
   （1268-1269ns/迭代），而 profiler 整核明确随字节线性增长
   （25.9/38.5/29.5/50.2/101.4/200.9µs，~3.2ns/KB），同字节数下
   load 方向比 store 方向贵 ~30%——simt 混合体的 SYS_CNT 读数
   不可用于字节标度判断。
3. simt 会话级双峰（E7/E8，同 kernel 相邻会话 2.8×）未归因。
4. 2×4096-elem（32KB 累加器）以上的 simt 体在本协议下会触发
   Vector core timeout（挂核），大累加器域未标。

**结论**：shipped 可加组合是与 E17g 同源的保守选择；simt 混合
组合律（超加性的定量形式）需在锁态 + grid=56 受控条件下重标后
才能定式——列为标定战役第一优先级。
